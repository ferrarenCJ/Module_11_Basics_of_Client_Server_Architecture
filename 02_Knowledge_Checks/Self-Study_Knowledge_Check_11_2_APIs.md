- XML-based
- Formal specification

## Question 2

### What does REST refer to in the context of APIs?

✅ Representational State Transfer architecture style

### Explanation

REST stands for:

```text
Representational State Transfer
```

REST is an architectural style used to design APIs.

---

## REST Principles

1. Uniform Interface
2. Client-Server Decoupling
3. Statelessness
4. Cacheability
5. Layered System Architecture
6. Code on Demand (Optional)

---

## Question 3

### What is an optional principle in the design of REST APIs?

✅ Code on Demand

### Explanation

Code on Demand is the only optional REST principle.

It allows servers to send executable code to clients.

Example:

```text
JavaScript
```

Most REST APIs do not require this feature.

---

## Question 4

### What is Swagger?

✅ It defines a method for defining APIs.

### Explanation

Swagger is a framework and toolset used to:

- Define APIs
- Document APIs
- Test APIs
- Debug APIs

Swagger creates interactive API documentation and allows developers to test endpoints directly from a browser.

## REST vs SOAP

| REST | SOAP |
|--------|--------|
| Lightweight | More structured |
| HTTP-based | XML-based |
| Easier to implement | More formal |
| Widely used in web APIs | Common in enterprise systems |

## Key Takeaways

- REST and SOAP are legitimate API styles.
- REST stands for Representational State Transfer.
- Code on Demand is the only optional REST principle.
- Swagger defines and documents APIs.
- APIs are fundamental to client-server communication and modern web development.
